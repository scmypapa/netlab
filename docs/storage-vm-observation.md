## 实现边界

- API → 现有 operation → 调度和原子预留 → 节点执行 → 当前资产事实 → 清理；沿用唯一任务队列。
- libvirt 负责硬件、快照、块任务和虚拟机迁移；成熟存储负责快照与克隆。模板制品和运行数据分别管理。
- 不改原平台，不修改生产节点。本地环境与测试制品复用，新增缓存放在 D 盘。
- 定向结果记录实际执行对象、规模、耗时、故障和残留。配置生成测试、模拟节点测试、原生执行验证分别列出。
- 原生采样是估算，PCAP 是实际捕获；容量报告同时记录输入流量、接收计数、采样率、裁剪和抓包丢失。

| 实例与存储清理 | 两侧 VM、测试 RBD 镜像、注册凭据和迁移 socket 均清理完成 |

测试中的 VM 使用真实 KVM 与空系统盘，验证的是原生执行、身份与存储交接；来宾业务连续性、Windows、NVRAM/TPM 和迁移后的业务网络未在本轮验证。

前序失败发生在测试脚本：复用 XML 解码对象重复追加磁盘；反向迁移采用普通运行 XML，CPU 模式与迁移 XML 不一致；清理向远端提交了源节点存储路径。脚本改用新解码对象、`DOMAIN_XML_MIGRATABLE` 和各节点真实执行配置，未增加产品回退或猜测规则。

Go 的 PostgreSQL 测试、Linux engine/node 测试与节点构建、Go/TypeScript 契约生成、前端生产构建通过。本轮未重复前端交互测试，也未修改 YINYU 平台或生产服务器。

控制面迁移在锁内预留目标容量并持久化到现有操作；现场确认唯一所有者后提交节点归属；源端清理只移除本地状态，保留目标仍使用的共享磁盘。未确认归属的失败任务保留预留，后续启动操作不能绕过交接。容器与本地 VM 复用原捕获、恢复及清理执行器，传输磁盘、卷与固件状态。执行结果带节点身份，迟到的源端结果不能覆盖交接后的目标状态。

目标拒绝迁移时，原任务确认源实例仍在、目标未运行，清理未启用的目标数据并恢复源状态；完成后任务记录为失败且已回滚，释放目标预留，允许后续环境操作。无法确认交接归属时保留当前阶段，原任务重试继续完成交接。实际 PostgreSQL 测试覆盖这两条路径：不兼容目标拒绝后可销毁环境，以及现场转移成功但响应丢失后的任务重试。

### 自动 NUMA 与 PCI 直通

NUMA 使用 libvirt 的自动 vCPU/内存放置与宿主 numad；API 支持 preferred、strict，默认交给宿主调度。真实 KVM 测试回读了运行域的 NUMA nodeset，并完成原生快照恢复。测试宿主只有一个物理 NUMA 节点，尚未验证多物理 NUMA 放置。

PCI 按整个 IOMMU 组分配，组身份来自完整 BDF 集合；节点仅提供已绑定 vfio-pci 的整组。资产绑定目标节点，原运行资产执行记录保存占用，原节点锁保证并发独占。libvirt managed hostdev 执行附加和释放，替换及磁盘恢复走原链路；模板和克隆清除宿主绑定。绑定修改由管理员执行。直通设备不跨节点迁移，设备内存状态不进入恢复点。

已通过 sysfs fixture 多功能设备/组身份测试、BDF 与 libvirt XML 测试、权限与克隆解绑测试，以及真实 PostgreSQL 下两个环境竞争同一组仅一个成功、释放后可再分配。工作台设备选择与草稿提交已通过浏览器测试。当前宿主没有可用真实 VFIO 组，物理直通执行未验证。
