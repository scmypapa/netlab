## 实现边界

- API → 现有 operation → 调度和原子预留 → 节点执行 → 当前资产事实 → 清理；沿用唯一任务队列。
- libvirt 负责硬件、快照、块任务和虚拟机迁移；成熟存储负责快照与克隆。模板制品和运行数据分别管理。
- 不改原平台，不修改生产节点。本地环境与测试制品复用，新增缓存放在 D 盘。
- 定向结果记录实际执行对象、规模、耗时、故障和残留。配置生成测试、模拟节点测试、原生执行验证分别列出。
- 原生采样是估算，PCAP 是实际捕获；容量报告同时记录输入流量、接收计数、采样率、裁剪和抓包丢失。

### Btrfs 与 CPU/NUMA

VM 模板支持 CPU 插槽、每核线程与来宾 NUMA 节点数，模板登记和资产资源变更使用同一规格校验。libvirt XML 生成与实际硬件回读均贯通，前端复用模板硬件编辑区。

目录存储根据实际文件系统自动识别 Btrfs，恢复点复用原生 CoW 文件快照；模板 backing 信息随恢复清单保存，目标节点按准备好的模板重新绑定。运行中 VM 仅在完成来宾冻结时使用该原生路径；其它现有目录执行路径保持 libvirt block backup 或停机转换。未增加另一套恢复队列。

`TestRealNativeSnapshotAndNUMA` 在第二 Worker 的独立 4 GiB Btrfs 测试盘通过：启动 4 vCPU / 512 MiB KVM，1 插槽、2 核、每核 2 线程、2 个来宾 NUMA 节点；停止后原生捕获，修改源盘，再恢复并验证原始 1 MiB 数据模式及 NUMA 配置。执行 1.25 秒，测试 VM 与文件已清理。

### Ceph RBD

`tests/fixtures/ceph-cluster.sh` 建立独立 Ceph 19.2.3 MON/MGR/OSD；OSD 使用 D 盘专用 32 GiB 稀疏文件及其 loop 设备。专用端口与密钥目录独立，未格式化现有磁盘。单 OSD、单副本用于接入验证。

## 节点迁移：原生执行面

2026-10-05：共享 RBD VM 的在线迁移使用 libvirt 原生 peer-to-peer tunneled migration，复用节点 mTLS 和原有执行槽。libvirt RPC 与内存通过这一条加密通道传输，宿主不开放额外 libvirt 或 QEMU 迁移端口。迁移由现有 `NodePlan` 的 `migrate` 阶段执行；没有创建恢复点、备份或第二套任务队列。

源节点和目标节点核对实例归属与共享磁盘。libvirt 完成目标持久化和源域移除后，执行器读取目标实际状态与配置；重复请求读取已完成的目标现场。取消请求中止原生任务，不自行启动源实例。控制面尚未接入迁移操作，当前没有向用户展示迁移入口。
