# Netlab v1.0.0

独立组网与虚拟资产管理，正式安装包面向 Ubuntu 24.04 x86-64。

## 功能

- Windows、Linux VM 与容器：模板导入、固件和硬件配置、创建、热更新与运维。
- OVN/OVS 网络：隔离网段、路由、外部 LAN、服务开放和 WireGuard。
- 存储：本地与 Ceph RBD、持久卷、原生恢复点、便携备份和节点迁移。
- 观测：资产通信图、接口抓包、sFlow 与资源历史。
- 同一套 API 和工作台；面板检查正式发布、查看日志并执行版本更新。

## 本次修复

| 问题 | 修正 |
| --- | --- |
| 卷任务在 queued 阶段失败后重试丢失输入 | 保留卷与执行节点，复用原任务重试 |
| 服务开放与 VPN 同时应用发生 OVN UUID 别名冲突 | 两类交换机使用独立事务别名 |
| 旧 Restic 无法正确识别缺失仓库 | 发布包固定携带 Restic 0.18.1，节点优先使用包内版本 |
| 节点升级中断后只等待，不启动原更新服务 | 继续原版本时重新启动同一 systemd 更新单元 |
| 隔离网段的重复 MAC/IP 导致流量误归属 | 抓包与采样保留接口和网段身份，统一按现场接口关联资产 |
| 会话过期后换账号仍保留旧账号环境缓存 | 进入登录页及登录成功时清除业务查询；保留当前身份查询的订阅 |
| 克隆后可能沿用源环境终端状态 | 环境身份变化时卸载原工作台，关闭源连接与编辑状态 |

抓包直接读取资产实际接口，保存多接口 PCAPNG；删除原 OVS 镜像和临时 veth 执行路径。

## 验证

- Windows 全仓 Go 测试连接真实 PostgreSQL，通过。
- Linux 全仓 Go 测试与 `go vet` 通过；Restic 原生仓库初始化、读写、恢复和清理通过。
- 真实 OVN/WireGuard：VPN 与服务开放共存后重新应用网络，通过。
- 真实 OVS/tshark：两个隔离 VLAN 使用相同 MAC/IP，流量分别归属正确，停止、重载与清理通过。
- 前端 57 项浏览器测试全部通过，包含账号过期后切换身份、克隆后断开源终端；前端类型检查与生产构建通过。
- 两 Worker、4 个容器与 2 台真实 Ubuntu VM：每节点 64 并发、2 MiB 响应、60 秒负载，同时采样、抓包与采集历史；完成 12677 次请求，失败 0，响应吞吐合计 417.97 MiB/s。两端 P95 为 1309.12 / 1915.52 ms，包含完整响应传输。创建及放置步骤 46.508 秒；包含来宾服务准备。清理错误 0。

## 容量与验证范围

第二 Worker 为第一 Worker 宿主上的嵌套 VM。上述抓包达到每节点 256 MiB 文件额度后停止；两节点 PCAPNG 记录内核丢包 162 / 18083。原始抓包并非无损记录。

额外的每节点 128 并发负载完成 6848 次请求，出现 42 次超时，集中在嵌套节点 VM 的 Python 测试服务；4 个容器目标无请求失败。该轮按失败记录保留，不作为通过结果。

多物理 NUMA、真实 PCI 直通、空白宿主完整安装和多节点正式版本强杀恢复尚未完成真实验收；已有实现与此前实测范围见 [实施记录](implementation.md) 和 [存储与虚拟机观测](storage-vm-observation.md)。
