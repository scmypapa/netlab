# 同类产品与使用设计

日期：2026-10-02。依据官方操作文档核对交互；本轮没有安装这些产品进行执行面测试。

## 1. 比较范围

| 产品 | 主要工作对象 | 已核对的使用方式 | 采用的设计 |
| --- | --- | --- | --- |
| Proxmox VE | 节点、VM、存储 | 左侧资源树选择对象，右侧显示对象状态与配置；控制台与启停靠近对象；底部近期任务，双击查看输出 | 对象上下文、局部动作、集中任务历史；基础设施信息留在资源入口 |
| Xen Orchestra | VM、模板、资源池 | 模板带出硬件与初始化设置；从现有 VM 制作模板；角色绑定用户或组 | 模板承担默认配置，用户只修改差异；共享使用命名角色 |
| Portainer | 环境、容器、应用 | 容器详情连接 console/logs/stats；高级参数分组；Duplicate/Edit 最终创建新容器并确认 Replace | 配置与运维在同一对象内；替换影响在提交时说清楚 |
| Containerlab | Lab、节点、接口 | 文件定义拓扑，annotations 单独保存布局；未运行时编辑，运行时操作；接口有统计、抓包和链路模拟；按节点模板快速添加 | 布局与执行配置分开；模板拖入画布；观察和诊断从接口进入 |
| GNS3 | Project、设备、连线 | 项目列表进入拓扑；专用连线模式、对象右键、多选；浏览器终端按设备分标签 | 拓扑是主工作区；可见操作与右键一致；多设备连接集中呈现 |
| Cisco CML | Lab、节点、接口 | Workbench 保持画布，右栏跟随选择，底部按需显示会话；连线默认第一空闲接口并高亮合法目标；Stop 与 Wipe 含义不同 | 接口选择有默认；工作窗按需打开；停机与清空数据分开 |
| EVE-NG | Lab、节点、网络 | Lab 内组织节点、网络和坐标；单节点及全 Lab 启停/Wipe；Professional 特性页列出在线以太网连线及 HTML5 控制台 | 设备与网络共同组织；在线连线按实际执行能力提供；状态与操作在画布对应对象上表达 |
| Harvester | VM、卷、网络 | VM 配置按 Basics/Volumes/Networks 分类；Save 与 Save and Restart 分开，待生效配置出现在对象列表 | 当前配置与待应用配置可辨；资源、网卡和磁盘使用各自合适的编辑器 |

版本依据：PVE 9.2 官方 GUI 文档；XO 模板页明确为 XO5，RBAC 按当前独立文档；Containerlab 和 Portainer 为当前滚动文档；GNS3 为 3.1 Web UI 文档；CML 使用 2.9 文档入口，部分静态页仍标 2.7，按 CML 2.x 交互参考；EVE 使用官方特性及 API 说明，未把过期 API 示例视为当前契约；Harvester 为 1.9。

## 2. 转化为本产品的使用逻辑

### 环境是工作入口

环境列表显示名称、状态、资产数和最近活动。新建选择环境模板或空白环境。已有模板可以直接“创建并运行”；空白环境进入画布，添加设备、连线后点“运行”。版本固定、容量预留、镜像准备和部署是这一动作的内部步骤。

环境创建后保持同一名称、身份与工作台。停止后仍能查看配置和数据；再次运行启动现有资源。环境模板用于复用，运行环境用于日常操作，二者不需要用户反复切换页面才能完成一个动作。

### 看现场与改配置分开

打开运行环境默认看现场，单击设备即可连接、查看文件、访问地址或资源曲线。点“调整环境”才进入执行配置编辑。新增、修改、移除集中形成一份待应用变更，提交前展示资产和数据影响。

排版、标签、分组与备注立即保存到画布视图，不进入部署任务，不制造新执行版本。拖动设备不应产生“环境需要升级”的提示。

容器参数修改可能需要替换实例，VM 参数可能在线生效或需要停机；提交预览显示具体结果。前端不能把相同的“保存”按钮赋予几种隐藏的中断语义。

### 所选对象决定信息和操作

中央拓扑保留网络全貌，左侧树定位设备和网段，右侧仅显示当前对象。主动作最多一项，其他动作进入对象菜单。多选才出现批量工具栏。

设备的连接、文件、指标和恢复点是局部工作区；网段的地址、路由、策略和接口是同一网段的局部工作区。抓包从实际接口或网段发起。任务和故障可以从对象进入，也可以从底部统一任务区进入，使用相同记录与详情。

### 减少重复输入

模板带出系统、硬件、资源、服务及初始化方式。添加时默认命名，自动选可用接口与地址；用户只决定要接入哪个网络及确需调整的规格。100 个资产支持复制、批量添加、网段折叠、搜索和列表视图。

默认角色为查看者、操作员、管理员，按环境继承。分享环境先选用户/组/Token 和角色，只有确需限制文件、资产编排或特定设备时才展开权限明细。guacd、libvirt、containerd 的机器权限由安装和节点服务负责。

退出编辑保留已保存草稿，现场入口提供“继续调整”；放弃草稿才移除未应用变化。保存设计为模板不复制系统数据，克隆环境与制作资产模板分别承担现有系统的复用。VM 使用“关机”，容器使用“停止”，强制停止作为独立操作。

## 3. 不沿用的交互代价

| 来源模式 | 本产品处理 |
| --- | --- |
| 大量节点、存储、池和底层配置菜单直接铺到日常页面 | 环境、模板、资源三个入口；宿主运维在资源详情 |
| 修改项目参数自动重建所有容器 | 计算实际差异，提交前列出需要替换的资产 |
| 保存配置与重启混在一个按钮中 | 草稿保存与应用分开；应用预览显示停机范围 |
| Wipe 同时清数据并重新分配网络身份 | 重建保留逻辑资产和接口身份；数据处理明确列出 |
| 默认增加管理网卡，用户自行处理多默认路由 | 沿用统一 NetworkSpec，明确主出口；不添加隐藏管理网卡 |
| CLI、文件路径和镜像命名约定成为 GUI 操作前提 | 稳定资源身份、模板导入、可视编辑与同一公开 API |
| 授权细项和底层连接权限一开始全部展示 | 默认角色和范围；细粒度约束按需展开 |
| 图形展示风格看起来像遥测，却没有对应采集 | 仅展示实际采集指标，未启用的数据提供采集入口 |

## 4. 页面组织

| 位置 | 日常内容 | 按需展开 |
| --- | --- | --- |
| 环境列表 | 名称、运行状态、规模、最近活动 | 当前任务、筛选与归档 |
| 环境工作台 | 拓扑或资产列表、所选对象、当前动作 | 任务、控制台、文件、观察、恢复点 |
| 资产模板 | 系统/类型、规格、服务、版本、可用情况 | 硬件、初始化、制品分发 |
| 环境模板 | 拓扑预览、规模、可创建版本 | 版本差异、参数、所需资产模板 |
| 资源 | 节点 CPU/内存/存储与状态 | 存储池、执行额度、宿主配置与诊断 |

节点表述使用 CPU 核数、GiB 和实例数。对象编号、执行步骤键、镜像摘要和节点许可属于诊断信息；日常页面使用名称和可读结果。

## 5. 自我审查场景

| 用户任务 | 应有的完整路径 | 设计检查点 |
| --- | --- | --- |
| 使用现有环境模板 | 选模板 → 命名 → 创建并运行 → 同一工作台看进度 | 一个业务命令完成，不要求先发布/准备/提交票据 |
| 从空白开始组网 | 添加网段 → 添加设备 → 连接 → 运行 | 网卡、地址及排版有默认；错误标记实际字段或对象 |
| 在运行中新增/替换设备 | 调整环境 → 编辑 → 预览影响 → 应用 | 保留其他设备工作；共享数据的回退边界可见 |
| 多设备操作 | 多选 → 批量动作 → 对象反馈 | 只操作选中对象；结果逐项可查 |
| VM 没有网络 | 选 VM → 控制台 → 检查系统 | 控制台不依赖 SSH/RDP 和来宾网络 |
| 对照多台设备 | 打开多个连接标签 → 切换或分屏 | 关闭标签不停止设备；页面切换不销毁环境 |
| 定位通信异常 | 选网段/接口 → 指标或通信 → 选连接 → 抓包 | 连线不冒充真实流量；采样与观测位置保留 |
| 只调整图形排版 | 拖动/分组/自动布局 | 不产生执行差异，不提示环境需重部署 |
| 删除/重建/恢复 | 选对象 → 列明磁盘与卷影响 → 一次确认 | 动词固定，数据保存或清空语义清楚 |
| 共享给同事 | 共享 → 用户或组 → 角色 | 默认继承；文件权限可独立限制 |
| 100 资产环境 | 搜索/折叠/列表 → 选目标 | 不要求缩小至文字无法辨认；操作仍在对象旁 |
| 部分操作失败 | 原工作台见失败对象 → 原任务看原因 → 针对性处理 | 当前状态依据现场结果；成功步骤不重复执行 |

以上是设计验收标准。执行面功能与性能仍按主设计的真实测试流程验收。

本轮检查结果：交叉审查修正了草稿保留、设计与数据复用、权限继承、正常与强制停止、多网卡折叠五处使用歧义。工作台原型完成五视图布局检查与八类局部交互检查；检查脚本为 `check-workbench.cjs`，浏览器为本机 Edge。原型数据用于展示交互，未连接节点和控制 API。
