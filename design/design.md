## 1. 产品主线

产品以“独立环境”为中心。用户先用模板组成网络环境，再运行、调整、观察和恢复它。模板与节点是环境的资源来源，不各自发展成一套平行产品。

```text
空白环境 / 环境模板 → 环境工作台 → 运行
                                    ↓
                           计算 + 网络 + 存储
                                    ↓
                           调整 → 观察 → 恢复 → 回收
```

三个主入口：**环境、模板、资源**。任务、连接和运行记录跟随对象呈现。会话审计作为操作记录的一部分，不成为产品主线。

模板页分为资产模板和环境模板。资产模板提供一个设备的系统、硬件、服务和默认规格；环境模板提供可复用的网络及设备组合。设计版本仍是不可变创建依据，固定版本由运行命令内部完成，日常用户无需逐页经过发布、计划和票据。

用户从环境列表创建、打开和管理环境。使用现有环境模板可以一次创建并运行；空白环境先在画布组成网络再运行。停止、再次启动和在线调整均回到同一工作台。配置、来宾数据与画布排版分别由执行修订、磁盘/恢复点、视图数据负责，三者不混用“保存”语义。

产品比较与交互决策见 [同类产品与使用设计](product-comparison.md)。已对照 PVE、Xen Orchestra、Portainer、Containerlab、GNS3、Cisco CML、EVE-NG 和 Harvester 的官方操作资料。

上层系统通过同一 API 完成全部操作。Web 工作台使用这套 API，不存在只有页面能操作的隐藏业务接口。底座管理技术资源，不读取赛事、队伍、计分或商店实体。

“专业程度”落实为五项能力的深度：

| 能力 | 完整使用闭环 |
| --- | --- |
| 计算与模板 | 导入或安装 → 确定虚拟硬件 → 固化模板 → 创建 → 调整 → 替换 |
| 网络 | 设计 → 地址与路由 → 部署 → 真实通信 → 在线修改 → 诊断 |
| 存储与恢复 | 运行盘 → 数据卷 → 恢复点 → 恢复或克隆 → 备份 → 保留与删除 |
| 环境生命周期 | 创建 → 启停 → 在线变更 → 迁移 → 故障处理 → 精确回收 |
| 运维与观察 | 选择对象 → 连接或文件 → 查看资源/流量 → 定位 → 执行处理 |

## 2. 技术决策

### 2.1 推荐架构

| 层级 | 选择 | 承担的工作 |
| --- | --- | --- |
| 控制面 | Go，标准 HTTP，pgx/sqlc | API、环境编排、调度、任务、授权 |
| 节点服务 | Go，mTLS，Linux 原生接口 | 执行计划、运行时适配、对象级观测 |
| 虚拟机 | libvirt + QEMU/KVM + SeaBIOS/OVMF + swtpm | 虚拟硬件、启停、热插拔、快照、迁移 |
| 容器 | containerd + runc | Docker/OCI 镜像、进程、可写层、资源限制 |
| 虚拟网络 | OVN + OVS | 二/三层网络、跨节点、DHCP、DNS、ACL、NAT |
| 链路模拟 | Linux tc/netem | 时延、丢包、带宽及恢复 |
| 状态与任务 | PostgreSQL | 配置、身份、占用、任务、结果 |
| 指标历史 | VictoriaMetrics 单机版 | 资源和接口计数的时间序列 |
| 前端 | React/TypeScript/Vite，Mantine，React Flow，Dagre，ECharts | 环境工作台、画布、文件、流量 |
| 远程连接 | xterm.js、noVNC、guacd | 终端、VM 控制台、SSH/RDP |
| 备份 | restic，文件目录或 S3 目标 | 快照数据的压缩、去重、加密和恢复 |

只自建环境产品所需的编排与适配。虚拟化、容器执行、交换路由、时序存储和备份均复用成熟实现。

Go 的选择依据是运行时生态、节点部署和类型化客户端，不把语言选择当作高性能证明。libvirt 使用正式 Go binding 和 libvirtxml；containerd 使用正式 Go client；OVN 使用类型化 OVSDB client。节点不靠拼接 shell 字符串执行主要业务。

### 2.2 备选路线比较

| 路线 | 判断 |
| --- | --- |
| Incus + 薄控制面 | 已有 OCI、Windows Agent、BIOS/UEFI、存储和集群，复用程度高。但原生网卡/磁盘型号选择较窄，完整遗留 Windows 硬件配置可能依赖 raw QEMU/QMP 覆盖。此要求下不作为默认底层。 |
| PVE API + 容器执行服务 | VM 与存储成熟；Docker 需另加执行体系，宿主环境也受 PVE 约束。适合管理已有 PVE 设施，不适合作为本产品最小部署形态。 |
| 抽取现有 .NET 平台 | 可减少部分迁移工作，但会继承当前模块、实体和执行路径耦合。复用已经验证的组件和规则，避免整体复制。 |
| Kubernetes/KubeVirt | 能力充足，控制组件和部署复杂度明显超过此产品需求。 |

### 2.3 Docker 镜像的完整语义

运行 Docker/OCI **Linux 镜像**，导入 OCI Registry、Docker 导出包和 OCI 包。containerd 的镜像配置负责继承启动入口、参数、环境变量、工作目录、用户与附加组。

底座明确接管卷、DNS/hosts、退出后的重启策略、日志和服务开放。镜像声明的 VOLUME 在导入时转成模板卷声明，首次创建卷时复制镜像对应目录的初始内容，随后挂载；重启和保留卷的替换不重复初始化。镜像的 HEALTHCHECK 只产生运行观察结果，不阻断发布或撤销已启动资产。

产品契约是镜像与资产 API；不承诺 Docker daemon API 或 docker-compose 完整兼容。多容器应用通过环境模板组织，不用隐含的 Compose 网络取代环境网络。

## 3. 领域与事实

```text
Project
 ├─ Template → TemplateVersion → Artifact / HardwareProfile
 ├─ EnvironmentBlueprint → BlueprintVersion
 └─ Environment → AppliedRevision
      ├─ Asset → Interfaces / Disks / Volumes
      ├─ Networks / Routes / Policies
      ├─ AccessEndpoints
      └─ RecoveryPoints

Operation → TargetChange / Steps / ActualResults
Node → Capabilities / StoragePools / Reservations
```

- **模板版本**：不可变制品、硬件与初始化方法。设备模板是带参数和端口声明的普通模板，Modbus 服务运行在资产里。
- **环境版本**：可重复创建的技术设计。新环境拥有独立网络和运行盘。
- **运行环境**：当前已应用的配置和资产集合。来源版本不替代现场事实。
- **资产**：稳定的逻辑身份。替换可以更换底层实例，资产、接口及数据卷身份继续保持。
- **操作任务**：一次用户动作的持久执行过程。所有耗时写操作进入这一套任务。
- **恢复点**：配置和相关数据的完整引用集合，有实际一致性等级。

PostgreSQL 是配置、资源所有权与操作事实源；libvirt/containerd/OVN 是实际执行状态的观测来源。接口分别表达配置和观测，不能用“期望运行”覆盖“实际停止”。节点失联时保留最后观测时间，状态为不可确认。

ID 不从显示名称、镜像摘要、修订号或日志中生成。Asset ID、接口 ID 是稳定逻辑身份；libvirt UUID、containerd 实例 ID 是具体运行实例身份。替换暂存的旧、新实例各自拥有唯一实例 ID，通过 metadata/labels 关联同一资产。数据库、域 metadata、containerd labels、OVN external_ids 保存对应的逻辑与实例归属。

## 4. 计算与模板

### 4.1 镜像制作与导入

支持三条制作路径，最后产生同一种模板版本：

1. 导入 Docker/OCI 镜像及镜像包。
2. 导入 qcow2/raw/vmdk/OVA 等 VM 制品；转换由 qemu-img/virt-v2v 完成，保存原始硬件描述和转换结果。
3. 上传 ISO，在模板制作工作区安装系统和驱动，再封装模板。运行环境无需重复安装系统。

导入的固件与磁盘控制器优先来自原配置/OVF。仅有裸磁盘且缺少描述时，在模板登记时确认一次系统和硬件配置；平台不反复启动试错，也不假定磁盘格式能说明固件类型。

模板版本保存制品引用、系统类型、默认资源、磁盘/网卡配置、初始化方式、服务声明及参数。摘要用于内容寻址和传输完整性，管理页使用名称和版本。

### 4.2 虚拟硬件

| 部分 | 深度设计 |
| --- | --- |
| 固件 | SeaBIOS 与 OVMF UEFI；Secure Boot 与密钥状态；每实例独立 NVRAM |
| 机器 | 版本化 i440fx/q35；创建后固定，不随节点升级变化 |
| CPU | vCPU/插槽拓扑、可迁移 CPU 模型、可选 host-passthrough、NUMA 与绑定 |
| 内存 | 硬限制、balloon、受来宾支持的在线扩容；缩减与变更中断范围明确 |
| 磁盘 | SATA/IDE/SCSI/VirtIO、启动顺序、I/O 限制、TRIM；控制器随模板固定 |
| 网卡 | VirtIO/e1000/rtl8139 等已验证型号；稳定 MAC、顺序、PCI 地址和接口 ID |
| 系统功能 | ACPI/APIC、时钟、串口、显示设备、QEMU Guest Agent 通道 |
| TPM | swtpm vTPM 2.0；独立持久状态；与恢复点和迁移一起管理 |
| 外设 | ISO 挂载/卸载；受节点能力和授权限制的 PCI/GPU 直通 |

常用硬件由模板默认带出。高级硬件在模板和所选 VM 详情中收纳，不成为创建每个环境时的一大片输入框。

Windows 7、Windows 10/11、Windows Server、Linux 分别以真实镜像验证。OS 名称不能替代原镜像驱动事实；已使用 SATA/e1000 的模板保留原硬件。旧 AD 镜像按完整环境复制，不在运行时执行 Sysprep 或更改域身份。

### 4.3 资产操作

统一提供启动、正常关机、停止、重启、暂停、恢复、重建与替换。VM 控制台不依赖来宾网络或 Guest Agent；Guest Agent 用于增强观测、正常关机和文件系统冻结。

资源变更按运行时与来宾支持区分即时生效或需停机生效。磁盘扩容同时表达块设备大小与来宾分区/文件系统大小；后者仅通过模板的标准初始化通道完成，不将宿主扩盘显示成文件系统已扩容。

## 5. 网络

### 5.1 统一网络模型

环境内统一建模网段、接口、路由和策略。虚拟交换机对应 OVN logical switch，路由对应 logical router，资产对应逻辑端口。用户在画布操作这些技术对象，系统编译为同一网络目标。

一个网段可跨多个节点，调度单位是资产，不再因网段限制必须放在同一节点。Geneve 负责跨节点转发；同节点走本地 OVS。各环境拥有独立逻辑网络和网关上下文，可以重复使用相同 CIDR。

支持 IPv4/IPv6、DHCP/RA、静态分配、DNS、网段间路由、ACL、安全组和 NAT。隔离默认按环境和网络关系实现，显式路由决定网段间连通。二层广播、ARP/NDP、MTU、组播和返回路径纳入数据面验证。

物理接入统一为 ExternalAttachment：物理网卡、VLAN 或现有桥。节点自动读出网卡信息；用户选择接入对象即可。占用与解绑由资源租约管理，销毁不改动接口原有地址和宿主管理网络。

### 5.2 多网卡与来宾网络

1. 每个接口固定 ID、MAC、地址和主出口属性。
2. 容器在应用启动前接好全部网卡，写入地址、路由和 DNS。
3. VM 通过 DHCP 保留地址，或模板的 cloud-init/Cloudbase-Init 通道获得完整接口配置；用 MAC 匹配，不依赖 eth0 或“以太网 2”等名称。
4. 主接口提供默认出口；其余接口提供直连及显式路由。DHCP 模式在接口级生成选项，避免多默认网关争抢。
5. 已有静态网络模板沿用其地址布局；环境网络在隔离范围内复用该布局，不强行改写 AD 网络。
6. 网段可以指定一个 DNS 资产。编译时解析成当前环境内该资产接口的地址，成员机直接查询该 DNS。

DNS、地址和路由都进入同一 NetworkSpec。域控 DNS 不通过平台公共解析器转发后冒充完整 AD DNS，不因镜像声明 Windows 就猜测它是域控。

VM 运维优先使用 hypervisor 控制台和 Guest Agent 通道，不额外塞入一张隐藏管理网卡。需要 SSH/RDP 的场景，节点在相应网络上下文中连接资产，避免宿主全局路由选错重叠网段。

### 5.3 对外访问

- 服务开放：入口 IP/端口 → 环境网关 → 目标资产接口。TCP/UDP 端口映射用于服务；全网络协议通过 VPN/路由入口访问。
- VPN：WireGuard 接入独立环境网关上下文，授权指定网段；撤销立即移除 Peer 和路由。
- IPv4/IPv6 入口地址按所用网关能力声明；手工/自动端口都使用同一端口注册表。
- 重叠 CIDR 环境的 VPN 客户端默认一次选择一个环境；并行接入使用各自访问前缀及网关地址转换，不改动来宾地址。
- 访问映射引用资产及接口 ID，不固定为旧 Worker 地址；迁移和替换重新应用实际目标。

创建入口先保留端口，再应用转发，再记录有效结果。失败释放本次占用；数据库提交失败时撤销刚创建的转发。长期映射的注册生命周期跟随映射，避免到期后被其他任务重复分配。

### 5.4 在线网络变更与链路模拟

网络、接口、ACL、路由和服务映射可通过统一变更入口调整。地址迁移和默认出口变化明确属于来宾配置变更；仅更新 OVN 不等于来宾已更新。计划标记受影响接口与资产，实际执行完成后推进已应用修订。

tc/netem 管理时延、丢包、带宽、抖动与方向。按逻辑策略解析当前全部接口，按节点批量应用。新接入接口继承网段策略；资产移除同步清理；失败恢复本批已经修改的接口。

## 6. 存储与恢复

### 6.1 存储对象

模板镜像只读；运行系统盘、数据盘和容器卷独立分配。模板删除受到当前引用约束，节点缓存释放不删除其他环境仍使用的主副本。

默认本地目录存储，VM 使用 qcow2 与 libvirt block jobs，容器使用 containerd snapshotter；持久卷单独登记。专业存储配置沿用同一 StoragePool 模型，支持经验证的本地快照存储和共享 Ceph RBD。Ceph 不成为单节点部署的前置条件。

每种存储池明确容量、可用空间、I/O、快照/克隆/迁移能力。能力来自实际驱动，不把所有操作对所有池都写成同样的按钮。

### 6.2 恢复点

| 对象 | 恢复点内容 |
| --- | --- |
| VM | 所有受管磁盘、域配置、固件/NVRAM、vTPM；选择状态保存时包含内存 |
| OCI 容器 | 可写层、所有受管持久卷、镜像和运行配置；不承诺跨节点透明恢复进程内存 |
| 环境 | 已应用配置、资产恢复点集合、网络身份和内部依赖 |

VM 快照与块任务由 libvirt/QEMU 执行，磁盘、NVRAM 和 TPM 使用同一捕获边界；支持的在线组合走原生快照，否则受控停机捕获。容器由实际 snapshotter 和卷存储能力执行。默认 overlayfs 可写层与普通目录卷在同一停写窗口内导出为固定恢复数据，完成后恢复运行；restic 读取这份固定数据。具备原生存储快照的池使用原生能力，普通目录不伪装成无中断快照。

一致性分三类记录：崩溃一致、文件系统一致、应用一致。Linux fsfreeze 提供文件系统一致；Windows VSS 依据实际 writer 成功结果标记应用一致。多资产环境恢复点是一个受控停写窗口内的集合，不承诺分布式数据库事务一致性。

恢复同时恢复硬件、磁盘与系统状态。按 libvirt Generation ID 语义通知支持的来宾发生恢复；老系统的 AD 恢复按整环境停机恢复执行，不把单机快照作为通用域回退方法。vTPM 绑定的加密卷恢复保留原密钥状态；独立克隆产生新的 VM 身份，完整克隆与模板部署明确区分。

恢复点删除按引用和 libvirt block job 合并链，避免后台长链无限叠加。显示真实占用与执行进度，不通过文件是否存在判断恢复完成。

### 6.3 备份与迁移

备份从稳定恢复点读取，由 restic 写入本地或 S3 目标，包含配置与全部受管状态。恢复可以回到原环境或克隆为新环境，后者创建新的环境隔离上下文。

节点迁移复用同一操作任务：保留资产/接口身份，准备目标容量，迁移状态，更新网络位置与入口，确认目标运行后释放源容量。

共享存储、CPU 兼容且设备可迁移的 VM 使用 libvirt live migration。默认非共享本地存储采用受控停机、复制完整磁盘/NVRAM/TPM 状态、目标启动；在线非共享迁移使用 libvirt 原生存储迁移，不复制仍在写入的 qcow2。迁移 RPC 超时后查询原生任务和源/目标运行身份，确认唯一所有者后才决定继续或回退，不能直接重新启动源实例。容器迁移为受控停止、搬迁卷和重新启动。

主机故障接管依赖明确 fencing 与可访问存储，复用迁移/恢复执行链。节点心跳超时只标记不可确认，不擅自重复启动。同一资源始终只有一个已确认的运行所有者。

## 7. 环境生命周期与热更新

### 7.1 唯一执行链

```text
API
 → 权限与业务约束
 → 写入目标变更和 Operation
 → 批量选择节点与原子容量保留
 → 准备制品/磁盘/网络
 → 节点执行
 → 汇总现场结果
 → 提交已应用修订和占用
 → 清理本次旧资源
```

PostgreSQL Operation 是唯一编排任务。原生运行时任务是它的执行步骤，不再增加 API operation worker、部署 worker、重建 worker 的重复队列。异步返回 202，直接查询这一项任务。

同一环境冲突变更顺序执行，不同环境并行。短事务领取任务、预留容量和写结果；网络调用期间不持有数据库事务。节点内部按真实能力限制创建、迁移和抓包并发，默认从 CPU 计算执行槽，存储带宽与容量用于调度。

### 7.2 创建

环境可以从环境模板或内联设计创建，名称与身份从创建起保持稳定。未运行环境仅保存配置；首次运行固定该配置快照，再分配网络、地址和资产。使用模板“创建并运行”由一个应用命令完成，调用方不需要串联发布、预热和部署请求。计划先完成 OVN 目标，再按节点并行准备和启动资产。

停止环境保留已应用配置、运行盘、卷和稳定接口身份，再次运行启动这些资源；“重建”才重新准备模板系统。日常创建不要求先把临时设计发布成公共模板。“保存设计为模板”生成可复用配置；“克隆环境”复制当前配置和系统数据；从已安装设备制作资产模板在该设备中执行固化。三个动作分别跟随设计、环境和设备，不混成一个含义不明的“保存”。

OCI 链路：制品与卷 → container/task → 全部网络与 DNS 配置 → Wait → Start。TaskExit 触发的重启复用这条启动链，保留逻辑资产、卷和地址，重新建立 task 与临时 namespace。VM 链路：磁盘/固件/TPM → 域定义与端口绑定 → 来宾初始化描述 → 启动。

“运行中”表示现场进程/VM 与网络资源建立。来宾初始化和业务服务健康作为独立观测，不作为发布门槛。进度来自真实任务步骤，应用未响应不会把已创建资产误回滚。

### 7.3 在线变更

提交一个目标差异，统一承载资产新增/替换/移除、资源调整、网卡/磁盘、网络和规则更新。版本升级也是将目标版本转成这一份差异。

预览列出新增、修改、删除，以及需停止的具体资产。普通用户只确认实际影响，不填写执行顺序。网络骨架在本产品中可以变更；来宾受影响配置与虚拟网络一起执行，不沿用旧产品仅能改资产的限制。

| 变更 | 执行和失败边界 |
| --- | --- |
| 新增 | 新资源就绪后接入；失败移除本次新增资源 |
| 替换 | 新实例先准备为停止状态；短暂停止旧实例、交接端口与卷、启动新实例；旧实例及原始数据保留到可回退阶段结束 |
| 在线资源/接口变更 | 原生 hotplug 支持时即时执行；需来宾更新的配置一起执行，受影响资产逐项回写 |
| 移除 | 先断开访问并停止，完成切换后再删除；破坏性清理最后执行 |
| OVN 规则 | 同一环境差异一次 OVSDB 事务，节点侧操作按批次执行 |

同批替换保持逻辑资产 ID、接口 ID、地址、授权和服务引用。旧实例与新实例不能同时占用同一 MAC/IP；切换前新实例不接入业务网络。

运行磁盘与卷的回退有数据边界。新实例已经写入共用卷后，回到旧实例不等于还原数据；完整回退要使用该数据的恢复点。页面和 API 用同一变更预览表达这一影响。

跨系统变更不是数据库事务。准备/切换阶段优先恢复原可用资源；完全回退时保持原修订。未完全回退时，提交实际已应用的资产/网络集合并推进修订，任务保留失败项；最终清理失败不撤销已经完成的配置提交。继续同一个操作任务清理旧资源。不能把现场部分完成改写成全部成功或旧配置全部恢复。

### 7.4 销毁与中断恢复

销毁顺序：撤销入口与 VPN → 结束连接/抓包 → 停止并删除资产 → 释放磁盘/卷 → 删除网络 → 释放容量和端口。用户保留的数据卷和恢复点按显式保留关系处理。

控制面重启后，从未完成 Operation 的具体目标及运行时稳定 ID 恢复步骤；仅检查这些对象，不扫描并重建全平台资源。节点重启后从自身受管对象恢复事件订阅。已经成功的资源创建不会因响应丢失再次复制。

节点失联期间不能宣称清理完成或释放其运行资源容量。节点恢复后继续原清理任务。任务取消只在未执行或可安全停止的阶段接受，运行时已进入不可中断任务时显示实际进度。

## 8. 运维与网络观察

### 8.1 同一对象上下文

环境工作台中央为拓扑或资产列表；左侧为资产/网段树；右侧为所选对象属性；下方按需打开连接或任务，文件和观察使用所选对象的工作区。打开运行环境默认看现场，点“调整环境”才编辑执行配置；退出编辑回到现场。关闭局部工作区恢复拓扑，不建立多张重复详情页。

视觉采用工具工作台结构：紧凑全局栏、环境操作栏和画布内工具栏。默认收起对象树，把主要宽度交给拓扑；按需打开搜索与树。网段使用轻区域边界和一致的连接颜色，VM、容器和设备使用不同图元，名称与地址贴近图元，系统版本进入对象详情。选中连接与设备同步突出，侧栏使用对齐属性行和接口区，不再用指标卡片与一排工作区按钮构成详情。

布局使用 8px 间距节奏；常规内边距 16px，区段间距 24px，按钮以紧凑工具控件呈现。编辑和提交从右侧抽屉展开，模板使用目录式列表。正常状态颜色克制，主操作、选中对象与异常各有明确层级。390/736/1024 宽度的布局不依赖把整屏缩小。

主操作跟随对象和状态：VM 可直接开控制台，容器可直接开终端；停止对象显示启动；其余操作放入一个对象菜单。多选后才出现批量工具栏。点击网段查看地址、路由、策略与成员接口；点击设备查看网络、硬件、服务及数据。没有对象选中时显示环境操作，不重复铺开所有设备配置。

创建连接默认选可用接口，用户只需确认目标网络。接口型号和数量来自模板；有多个可用接口时可在连线详情修改。连线保留两端接口名称，选中后展示地址与状态。右键是快捷入口，所有动作都有可见按钮或菜单及键盘等效入口。

画布的位置、备注、标签、折叠和显示偏好是独立视图数据，立即保存，不修改执行 revision。资产/网络编辑形成一份候选差异，可保存草稿、撤销草稿或应用；撤销不触发运行回退。应用前按新增、修改、移除分组，列出会停止、替换或清数据的具体对象。执行中标记实际受影响对象，其余资产继续可操作。

保存草稿后退出编辑保留草稿；再次打开默认看现场，提供“继续调整”。“放弃草稿”才删除待应用变化。草稿记录基于哪个已应用 revision，期间发生其他配置变更时重新计算预览，保留用户草稿供确认，不静默覆盖现场。

100 资产通过网段折叠、搜索、定位、列表、多选与批量添加处理；不靠缩小所有节点塞进一屏。桌面支持树/画布/上下文分栏；中宽屏收起树、保留对象选择；窄屏在拓扑、列表和所选对象间切换，表单按需打开，不永久挤三栏。

多网卡设备在画布中只有一个对象，接口分别连到实际网段。树中的网段成员只是该资产的定位引用，选择始终指向同一资产；折叠一个网段不隐藏设备在其他网段的连接。

连接窗按资产名分标签，可切换或分屏；关闭连接只结束连接。任务条只显示当前动作与失败数量，打开后显示对象、阶段和结果；原始日志、内部步骤键和资源编号在诊断中提供。现场状态在对象标题有一处权威呈现；任务成功、来宾初始化和服务响应各按其真实含义显示，不用一个绿色点替代所有结果。

| 动作 | 数据与网络身份 |
| --- | --- |
| 关机/停止 | VM 默认请求正常关机，容器默认正常停止；保留系统盘、数据卷、接口与地址 |
| 强制停止 | 立即终止执行；放在对象菜单，失败的正常关机不自动升级为强制停止 |
| 暂停/继续 | 保留内存执行状态和资源占用；网络服务在暂停期间不可响应 |
| 重启 | 保留磁盘、卷与接口，重新启动现有实例 |
| 重建 | 系统盘回到模板；保留或重置数据卷由该次操作明确选择；逻辑身份和接口保持 |
| 替换 | 更换系统模板/实例；数据卷和接口的交接影响在变更预览列出 |
| 恢复 | 配置及数据回到所选恢复点，覆盖范围与时间点清楚可见 |
| 移除/销毁 | 移除作用于设备，销毁作用于环境；确认列出被删除及保留的卷/恢复点 |

普通启停和开连接直接执行。替换、恢复、清数据或销毁只在实际影响需要时确认一次，不要求每次填写操作原因。

环境停止沿用各资产的正常停止方式；未停止对象在原任务显示具体结果，不把整环境写成已停止。

VM 提供开机即用的 VNC/串口控制台。SSH/RDP 使用用户授予的凭据和真实来宾服务；文件使用容器受管文件系统或 VM 的 SFTP/标准来宾通道。运行控制不依赖这些服务是否可用。

文件区使用目录树、列表、选择与上下文菜单，支持刷新、上传、下载、新建目录、重命名、移动和删除。传输全程流式，路径边界在实际文件通道验证，主站不保存中转副本。容器运行中操作实际容器文件系统，停止时挂载其受管 snapshot；统一解析容器路径，不直接拼接宿主路径。

### 8.2 观察的三个层级

| 层级 | 数据与使用 |
| --- | --- |
| 当前情况 | VM/容器资源、磁盘 I/O、网卡字节/包数/丢包；计数差分生成速率，VictoriaMetrics 保存历史 |
| 通信分析 | 选定环境启用 OVS IPFIX/sFlow，按接口身份聚合通信关系；采样数据明确展示采样比例与估计性质 |
| 包级诊断 | 对选中接口/网段创建 OVS Mirror/dumpcap 捕获任务，查看分段与下载 PCAP |

通信图使用实际接口和流记录，不根据拓扑连线虚构流量或推断单包路径。跨节点出口/入口记录分别保留观测位置，避免重复累加成一条真实业务流量。

抓包限制时长、文件大小和保留时间；部分分段失败显示部分运行和具体分段。文件写满、导出失败和观测丢失独立记录，不改变业务转发路径，不记录成访问失败。

选中通信连线，右侧显示连接、接口和规则；可以沿同一对象直接抓包、查看路由/策略或恢复链路限制。日常页面不展示所有原始日志和底层表。

## 9. API 与统一授权

API 基础路径 `/api/v1`，OpenAPI 为唯一源契约，前后端类型生成。没有 admin/open/internal 三套近似产品 API；机器执行通道独立认证。

| 资源 | API 组 |
| --- | --- |
| 模板 | templates、versions、imports、preparations |
| 环境设计 | blueprints、versions、validation |
| 运行环境 | environments、state、assets、networks |
| 环境变更 | environments/{id}/changes、operations/{id} |
| 资产操作 | assets/{id}/actions、files、sessions |
| 恢复与搬迁 | recovery-points、backups、migrations |
| 网络访问 | policies、endpoints、vpn-access、external-attachments |
| 网络观察 | metrics、flows、captures |
| 资源管理 | nodes、storage-pools、artifacts |

状态查询轻量化；资产和记录 cursor 分页。SSE 通知对象变化，携带事件游标并支持断线补读；控制台使用 WebSocket；文件上传下载为数据流。Webhook 从已提交事件发送，网络请求在事务外。

并发修改只使用对象 revision/ETag。创建环境和提交变更接受 clientRequestId，以项目内唯一键定位同一操作；不为所有接口建立请求摘要和重复幂等表。

用户和服务 Token 统一使用 project/environment/asset 范围授权；常用角色为查看、操作和管理，细项权限按需要配置。文件权限与远程控制分开，节点管理与环境管理分开。Token 权限是明确签发范围，不能继承创建人的管理员权限。

“共享环境”先选用户、组或服务 Token，再选查看者/操作员/管理员。默认范围为当前环境、向资产继承；需要文件限制或限定资产时展开同一授权模型的细项。页面入口与实际 API 授权一致，安装器负责远程连接组件的机器权限，用户不配置 CREATE_USER、节点证书或 guacd 内部账号。资源管理员与环境管理员职责分开，日常使用不穿过宿主权限表。

| 默认角色 | 权限 |
| --- | --- |
| 查看者 | 环境、设备、配置、指标与运行记录的只读访问 |
| 操作员 | 查看者权限，以及连接、文件、正常启停/重启/暂停、观察与抓包、已授权对象的链路策略和服务访问 |
| 管理员 | 操作员权限，以及资产/网络编排、重建、恢复、克隆、销毁和环境授权管理 |

细项编辑当前授权的正向权限集合，不叠加另一套拒绝规则。来自项目、组和环境的权限按并集合成；共享页显示实际生效权限和来源。下级取消勾选不会撤销上级授权，要缩小范围就修改产生该权限的授权。限制文件传输时可从操作员预设生成去掉文件权限的该次授权集合，若已有继承权限则在共享页直接显示。

`POST /api/v1/environments` 接受环境模板版本或内联配置，并可要求立即运行；`POST /api/v1/environments/{id}/actions` 启动/停止现有环境；`POST /api/v1/environments/{id}/changes` 预览或应用统一差异。草稿的保存不创建 Operation，应用才创建任务。画布视图使用独立 view 更新，不能把位置变化计入配置修订。同一个用例在 UI 与 API 有相同边界。

权限、资源归属、地址冲突、配额、文件路径和节点机器身份是必要边界；这些判断集中在其拥有者处，不在 API、应用服务和 Agent 各复制整套校验。

## 10. 部署与性能

### 10.1 单机到集群

**单节点**：一台具备 KVM 的 Linux 宿主；控制面、PostgreSQL、VictoriaMetrics 与节点服务可同机。控制面内嵌静态前端，无需前端服务或 Kubernetes；OVN 中央服务使用同一实现，本机执行也不切换为另一套桥接代码。

节点侧依赖 libvirt/QEMU、containerd/runc、OVS/OVN 及所需固件工具。安装器一次声明和安装固定版本组合。Docker-only 节点只需其实际运行能力，不被要求安装 KVM。

**多节点**：添加同构节点服务；控制面调度资产，OVN 自动跨节点。同网段可以分布到任意多个具备能力和容量的节点。

**控制面高可用**：多控制面实例共享 PostgreSQL，任务由数据库领取；OVN NB/SB 使用官方三成员 Raft；数据库采用成熟外部 HA 配置。VictoriaMetrics 单机部署不能宣称历史指标 HA，需要保持备份或使用其成熟集群形态。现有数据面在控制服务维护时继续转发。

guacd 仅在提供 Web RDP/SSH 时需要。VPN 组件随访问能力启用。Ceph、Registry 和对象存储可复用已有设施，单机不强制部署整套集群服务。

### 10.2 性能组织

| 通道 | 实现策略 |
| --- | --- |
| API | 索引与 cursor、轻量状态、批量查询、短事务；不反复传完整拓扑 |
| 调度 | 内存中准备不可变需求；短事务按节点容量原子预留；无长时间全局调度锁 |
| 执行 | 按资产和节点并行；同对象冲突串行；共享节点许可，不向同节点超发 |
| 网络 | OVN 控制事务与 OVS 数据面分离；真实业务包不经过控制 API |
| 运行状态 | 原生事件驱动，节点批量提交变化；重启时读取受管 inventory |
| 指标/流量 | 指标写成熟 TSDB；流记录批量聚合，限定保留；观测丢弃有计数 |
| 制品/文件 | 内容缓存、共享引用、流式传输，不经 JSON 字节数组 |
| 快照/备份 | 原生块任务和存储快照；长 I/O 独立额度，控制线程不等待大文件复制 |

容量以 CPU 核数、GiB、存储、实例与执行槽显示。自动额度基于主机实际资源，人工覆盖可以取消；调度仍使用同一资源预留模型。

设计验证负载分开考察：控制读写、50 环境×100 资产、真实业务转发、混合 VM/容器生命周期、抓包与备份并行。5000 资产是验证规模，不是已承诺容量；读 P95 200ms/受理 P95 500ms 是待验证目标。VM 启动时间依具体镜像和宿主记录，不能复用容器启动成绩。

## 11. 代码组织与复用

```text
cmd/
  controller/       # 单一 API/任务/调度进程
  node/             # 单一节点执行进程

  catalog/          # 模板、制品、硬件定义
  environment/      # 设计、版本、当前配置和变更计算
  operation/        # 持久任务、步骤、恢复
  fleet/            # 节点能力、容量、放置
  network/          # NetworkSpec、OVN、访问
  storage/          # 卷、恢复点、备份与迁移
  access/           # 身份、权限、连接与文件通道
  observe/          # 指标、流记录、抓包
  engine/           # libvirt/containerd/OVSDB 的实际适配
```

按资源所有权组织模块，不在每个模块重复创建 Controller/Facade/Manager/Service/Repository 转发链。模型与步骤以类型和清晰函数表达，不引入通用工作流 DSL 或插件市场。

优先复用当前 React Flow 画布、自动布局、模板/资产交互、文件视图、语义样式和已经验证的身份/网络规则。旧平台路由、赛事实体、生成 API、Guacamole 临时账号管理和部署队列不复制进新项目。复用代码逐项核对来源许可证与归属，保持新项目单独仓库、制品和数据库。

## 12. 设计交叉审查后的修正

| 初步设计风险 | 最终处理 |
| --- | --- |
| 将 Incus 的 VM 支持等同完整硬件兼容 | 核对其原生总线；选 libvirt，保留标准硬件配置 |
| 把 Docker 镜像可运行等同完整容器生命周期 | 明确 VOLUME、重启、日志、DNS 和服务开放的拥有者 |
| 容器启动后才接网 | 利用 containerd created 阶段完成网络，再 Start |
| qcow2 副本等同完整 VM 快照 | 恢复点包含 NVRAM/vTPM/配置与可选 RAM |
| 多对象变更失败一定能全量回滚 | 分准备、切换、破坏性清理；记录实际完成项和数据回退边界 |
| 心跳超时自动异地重建 | 保留唯一所有权；故障接管需 fencing 和可访问存储 |
| 主 NIC 标记能自动约束所有 guest 路由 | DHCP/初始化通道实际写入主出口，保留已有静态模板布局 |
| 替换的新旧实例共用同一个 hypervisor ID | 逻辑身份不变，具体运行实例使用独立 ID |
| 部分切换后数据库仍保留整份旧配置 | 实际已应用集合提交新修订，失败与清理状态单独记录 |
| 空 VOLUME 遮住镜像初始数据 | 首次分配卷时初始化，随后保持原卷 |
| 停写窗口后备份仍读取活动目录 | 先固定完整恢复数据，再由 restic 读取 |
| 迁移 API 成功说明非共享盘已经复制 | 专门传输磁盘、NVRAM、TPM，确认目标完整状态 |
| 恢复 AD 单机不会影响域 | 支持 VM Generation ID；旧系统使用整环境恢复策略 |
| 应用连通性检查决定发布 | 健康只观测；创建结果依据真实执行资源 |

## 13. 实施顺序与验证边界

1. **基础执行闭环**：独立仓库、API 与任务、模板导入、VM 完整硬件、OCI pre-start 网络、单环境创建/销毁。首先验证 Windows/AD 与混合资产，不先堆页面。
2. **专业网络与运行变更**：跨节点同网段、重叠 CIDR、多网卡 DNS/路由、资产及网络变更、入口与 VPN、调度和迁移。
3. **完整恢复能力**：磁盘/卷/NVRAM/vTPM 恢复点、克隆、备份、恢复、保留与清理，包含实际 BitLocker/AD 镜像。
4. **一体化工作台与观测**：环境画布、对象运维、流式文件、资源/流量历史、通信关系与抓包，全部对应已有真实 API。
5. **版本固化与规模验证**：固定宿主和依赖版本矩阵；真实并发、重启中断、故障接管、长期运行、备份恢复及迁移验收。

每步是同一完整产品的施工顺序，不以占位页面、未接执行器的接口或“后面再补”实现发布版本。

实施前需做一次聚焦执行面原型，确认固定发行组合中的三项边界：containerd 多网卡/DNS/pre-start、现代和遗留 Windows 硬件、完整 TPM/NVRAM 恢复及非共享迁移。它验证架构，不成为第二套产品或生产临时路径。

最终验证以一条 API 驱动流程贯通导入、发布、混合环境创建、通信、变更、恢复、迁移、抓包、文件及销毁。真实 OS 和设备服务必须参与；记录单步结果、阶段和现场残留。性能报告分别给业务转发与控制面成绩。

## 14. 安装与系统更新

正式发布来自 main 中的版本标签。一个 Linux 发布包包含控制面、节点程序和 Web；程序写入版本目录，数据库、模板、磁盘、证书与运行数据独立保存。安装和更新共用这套目录结构。

头像菜单提供「系统更新」：查看当前版本、最新正式版本、更新日志，检查并执行更新。控制面启动时和每六小时自动检查 GitHub Releases，只检查正式版本；更新由管理员确认，不自动安装。私有仓库凭据由安装配置提供，不进入浏览器或日志。

更新下载、核对发布包完整性，写入新版本目录，再原子切换并重启服务。独立 systemd 更新服务负责这条流程，进度在控制面重启后仍可查询。数据库只执行产品现有前向迁移，不恢复旧数据库或替换数据目录。开发环境可以查看发布信息，但不替换源码程序。

本轮先交付当前安装主机的更新。跨节点滚动更新属于后续安装器与节点交付范围，不把主站切换记录为全体节点已更新。

用户于 2026-10-04 取消最终集中验收；开发过程保留与改动直接相关的测试和构建。
