# 镜像与场景迁移

## 建立本次迁移清单

从交付说明、来源虚拟机配置与实际镜像取得：业务名称、文件路径、完整 SHA-256、资源规格、磁盘顺序、固件、机器类型、磁盘控制器、网卡型号、MAC、网卡顺序、IP/CIDR、网关、DNS、路由与防火墙规则。

将文档作为场景输入，按用户请求决定操作范围。保留场景中的软件与业务内容；路由器、交换机按 Netlab 原生组网实现。

## 导入模板

1. 读取 `GET /templates`，结合已有导入记录和来源 SHA-256 确定实际有变化的文件；哈希依据从真实文件或已有校验清单取得，同名与相同文件大小不能证明内容相同。核对源文件已完成导出且稳定。
2. 确认来源与目标可达；在支持的路径中选择减少中转副本的传输方式。使用可用的 SSH/SFTP 或平台支持的来源方式，按实际速度选择直连或既有代理。
3. 通过 `POST /templates` 导入。文件上传使用 multipart，先发送 JSON `template` 部分，再发送 `files`；`source` 指向上传集合中的主文件相对路径，OVF 和拆分 VMDK 保留目录关系。
4. Template 必填 `id,name,kind,os,version,source,resources`，并按镜像填写 format、hardware、disks、nicModels 等。容器 Registry 凭据使用契约的 `registry` 字段。
5. 记录 `Operation-Location` 和模板 `operationId`，等待模板 `state:ready`。`201` 仅证明模板记录创建，上传进度也独立于转换与准备进度。
6. 在源端与目标可读取的接收文件上比对完整 SHA-256；若平台执行格式转换或压缩，分别记录输入校验与转换后磁盘检查结果，区分文件哈希和逻辑内容一致性。

CPU 单位为核，内存 `memoryMiB`，磁盘容量 `diskGiB`。VM 使用整数 vCPU；容器 CPU 支持 0.01 核。镜像的虚拟容量、文件长度与物理占用分别记录。

当前模板格式枚举为 `oci`、`docker`、`qcow2`、`raw`、`vmdk`、`ova`、`ovf`、`iso`；按实际文件格式、系统及初始化能力填写，原有硬件信息优先从来源配置还原。

## 替换现有场景镜像

1. 确定用户要求仅更新模板，还是同步更新现有实例；沿用明确的“替换场景镜像”范围。
2. 将变化的文件作为新模板导入并准备完成；保存旧模板 ID 到新模板 ID 的映射。
3. 读取最新环境 spec，仅调整对应 `templateId`，保留资产 ID、名称、规格、网络及其余配置；使用 changes 预览并应用。
4. 按用户要求启动或重建相关实例；核对运行实例已经采用新模板，并检查对应服务。
5. 查询旧模板 `/references` 及 `/cache`，通过平台删除确认已失去引用的旧模板。仍被实例、环境或恢复点使用的文件维持完整，先报告引用对象。

模板注册完成、环境引用更新、运行盘替换、旧模板删除分别核对。通过平台解析依赖和释放引用，禁止使用文件系统强删来处理“仍被占用”。

## 组网还原

- 逻辑交换机由 `networks` 表示，显示名称与 `id`、`cidr` 独立；使用来源场景名称。
- 逻辑路由器使用 `routers`，路由器接口引用 network ID，静态路由使用 `routes`；网络隔离与链路规则使用 `policies`。
- `routers` 省略会建立默认路由拓扑；显式空数组保留二层网络。按隔离意图选择，防止默认互通改变场景。
- 相同 CIDR 可以属于不同路由域。多网卡按原顺序、MAC、网卡型号和主接口关系还原；检查每个地址所属网段和实际网关。
- 虚拟化层防火墙、路由和交换机配置单独重建；qcow2 承载来宾磁盘内容。
- 来宾适配优先采用平台现有初始化与网卡适配能力。固定网卡名、静态配置等问题先核对来宾实际状态，再修改明确授权的目标。
- 外部物理设备先选择节点已有网卡与外部网络，再发现并登记设备。登记描述物理设备，设备原 IP 由其自身配置管理。

验收依次核对资产数量与名称、硬件与网卡、来宾 IP/路由/DNS、允许与隔离关系、业务入口。仅在用户要求环境运行时启动，按实际授权选择必要的服务检查。

## 导回 PVE 或交付 qcow2

先明确导出对象：初始模板、当前运行实例，或指定恢复点。用户选择初始状态时读取模板基础镜像；当前实例含来宾修改，需要一致性处理后导出。

优先使用平台已有导出能力；当目标版本的公共接口没有对应导出时，使用已授权的只读存储访问取得选定源文件，记录源模板或实例身份。导出当前实例前按停机或受支持快照流程建立一致副本。

检查 `qemu-img info --backing-chain`。交付独立镜像时将完整依赖链转换为独立 qcow2，针对导出副本检查；源文件保持原状。对输出执行磁盘检查和校验，再按目标平台支持的固件、磁盘控制器、网卡型号与 MAC 导入。

目标 VMID 或磁盘已存在时，核对其身份和覆盖范围后执行替换。导入与启动分别处理，按用户要求决定目标电源状态。
