# 运行与维护

## 资源与环境占用

- `GET /nodes` 查询容量、已分配资源、CPU 分配比例、宿主预留内存、可分配内存及能力。CPU 分配比例表示调度策略，物理 CPU 容量保持原值。
- `GET /environments/{id}/metrics` 和 `GET /nodes/metrics` 查询趋势；时间、步长与 metric 过滤按当前契约设置。VM 内存按 QEMU RSS，容器按 cgroup，来宾内存与宿主进程占用分别解释。
- `GET /environments/{id}/storage` 返回环境实际占用：基础镜像与实例、卷、恢复点、近期报文等增量数据，并按实际物理位置返回容量和当前可用空间。
- 同环境共享的物理数据去重；多个节点各存一份时分别计量。多个环境可能引用同一基础镜像，环境总量简单相加会重复计算共享部分。
- 虚拟磁盘容量是来宾可见上限，稀疏文件物理分配按实际写入增长。文件长度、虚拟容量和文件系统物理占用分别核对。
- 当前可用空间采用调度规则：扣除池保留空间和正在执行的写入影响。磁盘报错按真实文件系统和存储池定位，避免通过调高声明容量掩盖不足。

## 清理与共享存储

先通过模板引用、恢复点、独立卷及当前任务确定数据用途。只清理用户授权范围内已失去引用的资源和明确的临时中转副本，保留仍在依赖链中的文件。

模板位置与引用：`GET /templates/{id}/cache`、`GET /templates/{id}/references`。这些管理员接口与前端入口名称可能不同，以操作目标识别。

存储池：`GET /storage-pools`。Ceph 状态：`GET /storage-pools/{id}/ceph`。节点候选设备：`GET /nodes/{id}/storage-device`。

Ceph 初始化涉及实际磁盘，先核对设备身份、用途与已有数据，并在执行前取得该设备使用授权。自动准备走节点存储设备接口及存储池现有流程；副本数按容量和容错目标选择，单副本提供共享访问而不提供副本冗余。

已有资产保留原存储，新配置不等于自动搬迁。迁移先查询 `GET /environments/{id}/assets/{assetId}/migrations`，选择兼容目标后向同一路径 POST；确认任务成功及实例位置后检查源端清理。

## 网络与运维

平台可访问、节点可连接、环境网络可通和来宾服务正常分别检查：

1. 控制面 API、身份和任务能读取。
2. 节点健康、KVM/containerd、存储及 OVN/OVS 状态满足目标能力。
3. 配置与运行态的网段、路由器、端口和网卡对应一致。
4. 从约定访问路径检查 ARP、路由、DNS和业务端口；失败按所在层定位。

SSH 配置位于资产 `/ssh`，探测主机指纹使用 `POST .../ssh/host-key`。密码认证与主机身份确认是两件事，按用户确认的指纹保存连接配置。

VNC、RDP、SSH、串口和文件传输按来宾能力与授权选择。来宾未开启 RDP 时沿用可用控制台，修改来宾服务须属于用户请求范围。文件权限与远程会话权限分别检查。

## 流量与风险

- `/environments/{id}/traffic` 提供 IPFIX 通信汇总；通信图呈现有流量的环境对象，广播/组播归入对应交换机关系。
- `/packets` 查询近期留存原包，支持时间、资产、接口、网段、端点和 Wireshark 显示过滤；`/{packetId}` 返回协议树与原始帧，`/export` 导出匹配报文。这些路径均接在 `/environments/{id}` 后。
- 通信汇总与原包留存分别工作。近期原包按环境压缩循环保留，覆盖后只能查询仍在保留范围内的数据；需要额外采集时使用 `/environments/{id}/captures`。
- `/environments/{id}/security` 查询 Suricata 风险、告警及检测状态。检测状态、查询范围与告警结果一起判断；零告警只表示当前范围内没有检测结果。
- 流量缺失先检查时间窗口、接口归属、IPFIX、留存和检测任务，再通过真实测试流量核验对应路径。

## 平台更新

1. `GET /system/update` 查看当前版本和更新活动，`POST /system/update/check` 获取正式发布版本与公告。
2. 核对已确认的版本、更新授权和现有任务。涉及数据库变更时按项目发布要求完成备份准备。
3. `POST /system/update`，JSON 为 `{ "version": "<已确认的发布标签>" }`。
4. 持续查询状态，分别观察下载、安装、等待任务、更新节点、重启与终态。控制面重启期间连接恢复后继续读状态。
5. 核对主站版本、节点更新结果、核心接口及既有资产状态；按本次变更选择一条真实业务链路检查。

更新失败先查看具体阶段与错误。下载超时检查控制面到 GitHub 发布包和实际重定向下载主机的网络；403 检查发布访问权限、API 额度与实际响应。通过正式更新流程重试，已运行的更新继续跟踪。手工覆盖程序、同时启动另一套安装流程不属于此更新路径。
